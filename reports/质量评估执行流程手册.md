# Vue 3 组件库 — 质量评估执行流程手册

> 版本：v1.0 | 创建日期：2026-08-18  
> 定位：每次执行全维度质量评估时的**标准操作流程（SOP）**，确保评估过程可重复、可追踪、可持久进行。  
> 配套文件：`reports/全维度质量评估报告.md`（评估结果输出文件）

---

## 一、流程总览

```
阶段1 静态检查 → 阶段2 测试覆盖率 → 阶段3 源码审查 → 阶段4 外观审计 → 阶段5 性能分析 → 阶段6 文档检查 → 阶段7 汇总分级 → 阶段8 报告输出 → 阶段9 跟踪闭环
```

每个阶段执行完毕后，**立即记录结果到本文件对应章节**，确保中途断电/压缩后可从断点恢复。

## 二、执行前准备

### 2.1 环境检查清单

```bash
# 1. 确认 Node.js 版本
node -v  # 要求 >= 18.0.0

# 2. 安装依赖（如 node_modules 不存在或 package.json 有变更）
npm install

# 3. 确认 git 状态（评估前应基于干净的 working tree 或已知变更）
git status
```

### 2.2 关键文件路径确认

| 文件 | 路径 | 用途 |
| :--- | :--- | :--- |
| 组件库入口 | `src/components/index.ts` | 确认导出组件清单 |

| package.json | `package.json` | 依赖分析 |

## 三、各阶段执行步骤

### 阶段 1：静态检查（自动化）

**目标**：确认 TypeScript 和 ESLint 零错误。

**执行命令**：

```bash
# TypeScript 类型检查
npx vue-tsc --noEmit 2>&1 | Tee-Object -FilePath tsc-report.txt

# ESLint 检查
npx eslint src --format json 2>$null | Out-File -FilePath eslint-report.json -Encoding UTF8
```

**记录格式**：

```
- vue-tsc: [PASS/FAIL] — X 个错误，耗时 Ys
- ESLint: [PASS/FAIL] — X 个 errors，Y 个 warnings，耗时 Zs
```

**当前结果（2026-08-18）**：
- vue-tsc: **PASS** — 零错误，耗时 18.7s
- ESLint: **PASS** — 零 errors，耗时 14.8s

### 阶段 2：单元测试与覆盖率分析

**目标**：统计测试通过率和覆盖率，判断是否达到门禁阈值。

**执行命令**：

```bash
npx vitest run --coverage 2>&1 | Tee-Object -FilePath vitest-report.txt
```

**记录格式**：

```

- 测试用例数: X (通过 X / 失败 X)
- 覆盖率: 行 X% / 分支 X% / 函数 X% / 语句 X%
- 门禁阈值: 行 31% / 分支 26% / 函数 28% / 语句 29%
- 门禁状态: [PASS/FAIL]
- 覆盖率最低的 3 个文件:
  1. 文件路径 — X%
  2. 文件路径 — X%
  3. 文件路径 — X%
```

**当前结果（2026-08-18）**：
- 测试文件数: **0**（tests/unit/ 目录已被删除）
- 测试用例数: **0**
- 覆盖率: 行 **0%** / 分支 **0%** / 函数 **0%** / 语句 **0%**
- 门禁状态: **FAIL**（全部不通过）
- **恢复方案**: `git checkout HEAD -- tests/` 或重新编写

### 阶段 4：外观审计（视觉一致性）

**目标**：检查设计令牌覆盖率、硬编码色值、交互状态一致性。

**执行步骤**：

```bash

# 人工阅读 src/components/tokens.css，记录变量清单

# 4.2 搜索硬编码色值
# 使用 grep 搜索十六进制色值
grep -rn "#[0-9a-fA-F]{3,8}[^a-zA-Z0-9]" src/components/ --include="*.vue"

# 4.3 搜索硬编码 rgba
grep -rn "rgba\([0-9]" src/components/ --include="*.vue"

# 4.4 检查交互状态
# 人工审查 :hover/:focus/:active/:disabled 在各组件中的实现
```

**记录格式**：

```
- 设计令牌总数: X 个（颜色 X / 间距 X / 圆角 X / 阴影 X / 动效 X / z-index X）
- CSS 变量使用率: 约 X%
- 硬编码色值: X 处（列出文件:行号）
- 交互状态一致性: A/B/C/D
- 尺寸协调性: 对比表
- 暗色模式: [支持/不支持] — 实现方式
```

### 阶段 5：性能与内存分析

**目标**：识别性能瓶颈和内存泄漏风险。

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
| :--- | :--- | :--- |
| 大列表性能 | 检查 DataTable/Select/Tree 是否有虚拟滚动或分页 | 1000+ 数据不卡顿 |
| 高频事件防抖 | grep 搜索 debounce/throttle | Input/Scroll/Resize 有防抖 |
| 内存泄漏 | 检查 onMounted/onUnmounted 配对 | 所有事件监听/定时器/Observer 有清理 |
| 包体积 | 分析 vite.config.ts external/manualChunks | peerDeps 排除 + chunk 拆分 |
| 懒加载 | grep 搜索 defineAsyncComponent | 非首屏组件可选懒加载 |

**执行命令**：

```bash
# 检查定时器/事件监听清理
grep -rn "onBeforeUnmount\|onUnmounted" src/components/ --include="*.vue" --include="*.ts"

# 检查 debounce/throttle
grep -rn "debounce\|throttle" src/components/ --include="*.vue" --include="*.ts"

# 检查 defineAsyncComponent
grep -rn "defineAsyncComponent" src/components/ --include="*.vue" --include="*.ts"
```

**当前结果（2026-08-18）**：
- 大列表: DataTable 有 virtualScroll Props，Select 无虚拟列表
- 高频事件防抖: **缺失**（Select 搜索无 debounce）
- 内存泄漏: **无风险**（所有 composables 有 onUnmounted 清理）
- 包体积: external + manualChunks 配置完善
- 懒加载: 未使用 defineAsyncComponent

## 四、持久化执行机制

### 4.1 断点恢复

每次评估时，先阅读本文件的「当前结果」部分，了解上次评估状态。如果某个阶段的「当前结果」为空或标记为「待重跑」，则从该阶段继续执行。

### 4.2 版本化记录

每次评估后，将本文件中的「当前结果」更新为最新数据，并在文件头部更新版本号和日期。

```markdown
# 版本历史

| 版本 | 日期 | 评估人 | 变更摘要 |
| :--- | :--- | :--- | :--- |
| v1.0 | 2026-08-18 | AI | 初始评估：B 级，8 个 P1，0 个 P0 |
| v1.1 | YYYY-MM-DD | — | 修复 P1-001/P1-008 后复评 |
```

### 4.3 自动化集成建议

```yaml
# .github/workflows/quality-assessment.yml
name: Component Library Quality Assessment
on:
  schedule:
    - cron: '0 2 * * 1'  # 每周一凌晨 2 点
  workflow_dispatch:
jobs:
  assess:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm run test:unit
      - run: npm run build
      # 生成覆盖率报告
      - run: npm run report:coverage
      # 上传报告 artifact
      - uses: actions/upload-artifact@v4
        with:
          name: quality-report
          path: reports/
```
