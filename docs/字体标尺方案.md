# 复合字体标尺方案（P0-2）

> 目标：吸收 BoardUI 的「size + 行高 + 字重 + 字距 一次给齐」这套做法，
> **但只用我们密排真正需要的档位** —— 不抄它从 64px 到 11px 的六档 Display 标尺。
>
> 状态：**已落地（2026-11-07，作者授权）**。五档先上线，同日按实测用量补了 subtitle(15) / title(18) 两档，
> 现为 **7 档 / 16 条工具类**。落地细节与闸口见 [boardui 对照分析](./boardui-对照分析-2026-11-07.md) §9.1 / §9.10 / §9.11。
> 原文保留作为决策记录 —— 下面的「提案」一节是当时的判断，实际实现比它多两档。

---

## 1. 为什么我们该有复合标尺

现状：字号是裸令牌（`--vcl-fs-9…28`），行高和字重由各组件各写各的。

实测代价（`grep -ro "var(--vcl-fs-N)" src` 计数）：

| 档位 | 引用数 | 用途印象 |
| --- | --- | --- |
| `fs-12` | **90** | 表格正文、表单标签、说明文字 |
| `fs-13` | **78** | 主正文 |
| `fs-11` | **50** | 次要说明、表头、面包屑 |
| `fs-20` | **39** | 区块标题 |
| `fs-10` | 14 | 极小标注 |
| `fs-14` | 9 | 控件文字 |
| `fs-18` | 6 | 弹窗标题 |
| `fs-9` / `fs-15` | 5 / 5 | 角标、特殊场景 |
| `fs-22` | 4 | — |
| `fs-16` | 3 | — |
| `fs-28` | **1** | 页标题（全库仅一处） |

问题不在字号本身，在**同一个字号在不同文件里配了不同的行高与字重**：
`fs-12` 被引 90 次，就意味着至少有十几种 `line-height` 写法并存，视觉上「同级的字」看起来不同级。

BoardUI 的解法是把「排版决策」从组件里收走：一条 `text-body-medium` 同时给齐四个属性。
**这条值得抄。**

## 2. 不抄的部分（明确）

| BoardUI 有 | 我们 | 理由 |
| --- | --- | --- |
| Large Title 64/80 | **不设** | 全库最大实际用量 28px（1 处）。64px 在我们的密排里没有位置 |
| Display 1–4：56/72、48/64、40/54、32/44 | **不设** | 同上：0 引用。设了就是「设计系统里躺着的死档位」 |
| Title 1/2/3：24/34、20/26、… | **只留 20 一档** | 20 有 39 次真实引用；24/26 档没有 |
| 每族 × 4 字重（400/500/600/700） | **每族只给实际用到的字重** | 700 在我们这里几乎只出现在表头/页标题 |

**结论：BoardUI 六档 Display 是营销首屏的需求，不是组件库的需求。** 抄它的「做法」，不抄它的「档位」。

## 3. 提案：五档复合标尺（密排版）

命名对齐我们的 `--vcl-` 命名空间（ADR-004），语义按**用途**而不是按尺寸命名（尺寸会随场景变，用途不会）。

```css
/* 行高 = 字号 × 系数后取整；字距沿用 BoardUI 的「小字加正距、大字归零」经验 */
--vcl-text-caption-{weight}:     calc(11px * var(--vcl-scale)) / lh 15px  ls 0.2px
--vcl-text-label-{weight}:       calc(12px * var(--vcl-scale)) / lh 16px  ls 0.1px
--vcl-text-body-{weight}:        calc(13px * var(--vcl-scale)) / lh 20px  ls 0
--vcl-text-control-{weight}:     var(--vcl-ctrl-font-size)     / lh 20px  ls 0
--vcl-text-heading-{weight}:     calc(20px * var(--vcl-scale)) / lh 28px  ls 0
```

字重按档位给（不搞 4×5=20 个组合）：

| 档 | 提供字重 | 说明 |
| --- | --- | --- |
| caption | 400 / 500 | 角标、辅助说明 |
| label | 400 / 500 / 600 | 表头、表单标签需要 600 |
| body | 400 / 500 | 正文与强调 |
| control | 400 / 500 | 控件文字 |
| heading | 500 / 600 | 区块标题、弹窗标题 |

合计 **12 条**（约 36 行声明），不是 BoardUI 的 100+ 条。

## 4. 落地方式（三段式，可回退）

1. **只新增，不改旧**：新令牌与 `--vcl-fs-*` 并存。旧令牌一个不动 —— 零回归风险。
2. **逐组件迁移**：优先迁 90 次引用的 `fs-12` 与 78 次的 `fs-13`，一处组件一个提交，可单独回退。
3. **加闸口**：迁完后新增 `check:type-tokens` —— 组件 CSS 里出现「`font-size: var(--vcl-fs-*)` 且同行/邻近无 `line-height`」即提示，防止新旧混用长期共存。

## 5. 验收口径

- `check:css-scale`：`calc(Npx * var(--vcl-scale))` 不变 —— 复合标尺里的字号也必须走等比。
- `check:css-tokens`：新令牌必须在 `tokens.css` 声明（不是 fallback 兜底）。
- `check:contrast`：字重/字号变化不得让任何既有配色跌破对比度阈值。
- 视觉回归：至少 3 页（DataTable / FormDesigner / 登录页）逐像素比对，允许行高 ±1px。

## 6. 需要确认的一句

> 「tokens.css 追加 12 条复合字体令牌（只增不改），可以吗？」

确认后我按 §4 的三段式走，先只做「新增」，迁移另开提交。
