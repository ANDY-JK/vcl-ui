# ADR-003：容器查询替代视口断点——布局跟容器走

- 状态：已接受（2026-10-21 追记；决策形成于 2026-09-28~10-02 的 `cq` 系列提交）
- 决策人：维护者
- 关联：`src/components/**/*.css` 的 `@container`、`scripts/check-constants.mjs` 的断点登记、`docs/tech-debt.md`

## 背景

组件库的传统做法是**视口断点**（`@media (max-width: 768px)`）。它有个根本缺陷：

> **组件不知道自己在多宽的容器里。** 同一个 `DataTable`，全屏时是 1200px 宽、塞进侧栏时是 400px 宽，而 `@media` 只看浏览器窗口 —— 两种情况拿到同一个断点判定。

后果很具体：表格在侧栏里挤成一团却仍走"桌面布局"；或者反过来，大屏上放进窄卡片却塌成移动端。

## 决策

**布局切换一律跟容器走**（`@container`），视口断点只保留给真正的页面级布局。

具体：

- 组件内部响应式用 `@container <name> (min-width: …)`，容器由组件自己声明 `container-type`。
- demo 层也全面改用 `@container demo`（11 处 `@media` 改造）。
- 断点值仍走令牌（`--vcl-bp-sm/md/lg`），JS 侧同值（`BP_SM/BP_MD/BP_LG`），两处由闸口对账。

## 后果

**正**：

- 同一组件在任意容器宽度下都表现正确 —— 这是"组件"应有的语义。
- 侧栏/抽屉/弹窗内嵌表格这类场景不再需要宿主写覆盖样式。

**负**：

- **容器查询有兼容下限**（Chrome 105+ / Safari 16+ / Firefox 110+）。老浏览器降级为"永远最宽布局"。
- **调试更难**：DevTools 里容器断点不如媒体查询直观，新人容易误以为样式没生效。
- **`container-type` 会影响布局**（`inline-size` 会建立包含块），个别绝对定位元素需额外处理。
- 与宿主自己的 `@media` 规则**会打架**：宿主若在外层加视口断点，两套逻辑叠加后行为难预测（已写进排障文档）。

## 复核触发条件

- 需要支持 Chrome < 105 的宿主 → 加 `@supports` 回退或改回 `@media`。
- 出现"容器查询与宿主媒体查询叠加导致布局错乱"的实际案例 → 在文档里明确"不要在外层加视口断点"。
