# ADR-004：设计令牌全量加 `--vcl-` 命名空间

- 状态：已接受（2026-09-30 落地，提交 `18042e6`；本文 2026-10-21 追记）
- 决策人：维护者
- 关联：`src/components/tokens.css`、`scripts/gen-theme.mjs`、主题编辑器、`docs-site/guide/migration-2.0.md`

## 背景

1.x 时期设计令牌是无前缀的通用名：`--color-primary`、`--space-4`、`--fs-sm`、`--z-modal`。

这些名字**在宿主页面里极易撞车**：

- 宿主自己的 CSS 变量、其他组件库（Element Plus 用 `--el-*`，Arco 用 `--primary-6` 之类）、
  甚至浏览器将来可能定义的同名变量。
- CSS 自定义属性**没有作用域隔离** —— `:root` 上定义的就是全局的，撞车时后加载的赢，
  表现为"我的主题在某个页面突然失效"，极难定位。

实测影响面：**176 个文件**改名、5 处闸口与主题编辑器需要同步对齐。

## 决策

**全部公开设计令牌加 `--vcl-` 前缀，无一例外。**

```css
/* 1.x */
--color-primary: #4f6ef7;
/* 2.0 */
--vcl-color-primary: #4f6ef7;
```

边界划得很清楚：

- **公开令牌**（`tokens.css` 里声明的）→ 全部加前缀，这是**契约**。
- **组件内部旋钮**（`--fb-*`、`--nav-*` 等声明在组件文件里的）→ **不加前缀，也不属公开契约**。
  宿主依赖它们不受支持。

迁移口诀只有一条：**旧令牌名前加 `vcl-`**。宿主用一条 `grep` 就能找全（已写进
`docs-site/guide/migration-2.0.md`）。

## 后果

**正**：

- 命名空间隔离，宿主可放心用 `--color-primary` 这类通用名而不影响库。
- 一眼能看出"这个变量来自组件库"（读代码/看 DevTools 时省一次搜索）。
- 主题生成器与主题编辑器的配置键同步换名，**一条规则贯穿到底**，没有"有的加有的不加"的例外要记。

**负**：

- **破坏性变更**：1.x 宿主凡覆盖过库令牌的都要改（这是 2.0 的主要 breaking change 之一）。
- 令牌名变长，手写 CSS 时略啰嗦。
- 内部旋钮**没有**前缀这件事本身是个不一致 —— 但把它们也纳入契约的代价更大（会锁死实现细节），
  所以选择"明确声明它们不是契约"。

## 复核触发条件

- 若将来要支持"多主题实例并存"（同一页面两套主题）→ 前缀不够，需要改为 `@scope` 或
  容器级变量声明，那时本决策要重审。
