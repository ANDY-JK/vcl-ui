# 模块耦合审查报告（"勾连"专项）

> **审查日期：** 2026-08-24
> **审查范围：** `src/components/` 全部模块（_internal / amap / basic / chart / data / feedback / form / form-builder / layout / login / nav / route-planner / shared / storage / wc）
> **审查方法：** import 图循环依赖扫描 + 三路子代理并行深度审查（form-builder、amap/route-planner/storage、_internal 与各组）+ 关键发现人工复核
> **结论：** 无循环依赖（DAG 干净），但存在 14 处高危"勾连"点——共享可变单例、跨域直连内部实现、同一算法多处复制、全局 DOM 查询。改一个组件导致另一个组件出问题的风险集中在这 14 处。

---

## 一、总体结论

| 区域 | 耦合评分 | 主要问题 |
|------|---------|----------|
| form-builder | **8/10（严重）** | 5 套并行类型枚举、存储 key 算法复制、进程级注册表单例、富文本 querySelector 串扰 |
| amap / route-planner / storage | **7/10** | 11 处深路径绕过公共出口、AMap 初始化时机锁死、RoutePlan 对象图三模块原地改 |
| _internal 与各业务组 | **6.5/10** | ModalManager/Toast/z-top 全局单例、useVoice/useBeep 模块顶层副作用、单一入口一锅端 |

**为什么会出现"改这个坏那个"：** 三个根因反复出现——
1. **共享可变单例**：模块级 `ref`/`let` 被多个组件实例共享（useModalManager、amap-key、fieldRegistry、Toast 队列、markLayerOpen 时间戳）。
2. **绕过公共出口直连内部实现**：route-planner 11 处 `import from '@/components/amap/amap-service'`，designer 子组件直连 `../FormRenderer.vue`。
3. **同一算法/常量多处复制**：collectKey 指纹算法、schema 版本号、估算参数（roadFactor/avgSpeedKmh）、字段类型枚举各写 2-5 份。

## 二、高危发现（按严重度分级）

### 🔴 高 — 改一处必然/大概率连带破坏其他模块

#### H1. useModalManager 是模块级单例，跨域共享同一"当前弹窗"栈
- **文件：** `_internal/useModalManager.ts:4`（`const activeCloseFn: Ref<...> = ref(null)`）
- **消费方：** `feedback/Drawer.vue:84`、`layout/ModalBox.vue:105`、`_internal/useFocusTrap.ts:113`
- **问题：** 模块级单例 + 全局互斥"新开即关旧"。页面任何 ModalBox 打开会同步关闭任何 Drawer，反之亦然。layout 域改动直接影响 feedback 域行为。
- **影响：** 多弹窗组件并存页面；改 ModalBox 新增关闭路径会改变 Drawer 的关闭行为。
- **建议：** 改为主键 scope 隔离的 Map 或 provide/inject 按组件树隔离。

#### H2. Toast 队列/计数是组件实例级，但 window.__toast 是全局的
- **文件：** `feedback/Toast.vue:34-35`（`toasts`/`nextId` 每实例一份）、`Toast.vue:119`（`Object.defineProperty(window, '__toast', ...)`）
- **问题：** 页面挂 2 个 `<Toast>` 时两实例 id 都从 1 计数，`remove(id)` 会误删另一实例的同 id toast；`window.__toast` 绑定"最后挂载的实例"，该实例卸载后 dangling。
- **影响：** DataTable、ImagePreview、login 四页、FormBuilder 均依赖 Toast。
- **建议：** 队列+计数+`__toast` 收敛为单文件模块级单例 store，组件只做渲染层。

#### H3. amap-key 是进程级可变单例，且 AMap 初始化锁死在模块加载时刻
- **文件：** `amap/amap-key.ts:31-53`（模块级 `_override`/`_warned`）、`AmapWidget.vue:65-78` 与 `RouteMap.vue:24-35`（模块作用域同步执行 `initAMapApiLoader` + 覆写 `window._AMapSecurityConfig`）
- **问题：** `setAmapKey()` 被设计为运行时可变，但地图 SDK 的 key 在 import 时已被捕获——运行时 set 对地图渲染无效（REST 生效、JS API 不生效）。两页面配置不同 key 无法共存；AmapWidget 与 RouteMap 各自初始化互相覆写。
- **建议：** 移除模块级初始化，收敛为单一 `initAmap()` 提供者并响应 key 变化。

#### H4. route-planner 11 处深路径直连 amap 内部文件，完全绕过公共出口
- **文件：** `route-planner/` 下 `RouteResult.vue:9`、`RouteMap.vue:10`、`utils/excel-import.ts:6`、`utils/coordinate-resolver.ts:13`、`utils/driving-direction.ts:12,74`、`utils/gaode-navigator.ts:12,13`、`utils/route-planning.ts:18`、`composables/useStoreData.ts:5`
- **问题：** 全部直接 `import from '@/components/amap/amap-service'` / `amap-key`，而非 `@/components/amap` 公共出口。改 amap-service 内部文件名/签名时，即使公共 API 不变，route-planner 也编译失败。
- **建议：** 统一改 `from '@/components/amap'`。

#### H5. amap 公共出口自相矛盾：`normalizeChinaLatLon` 只在总入口有
- **文件：** `amap/index.ts`（导出清单缺 `normalizeChinaLatLon`）vs `components/index.ts:36`
- **问题：** 从 `@/components/amap` 无法导入该函数，从 `@/components` 可以。两个"公共出口"表面不一致，是 H4 深路径依赖的直接诱因。
- **建议：** `amap/index.ts` 补齐导出。

#### H6. fieldRegistry 是模块级可变单例，跨组件实例共享
- **文件：** `form-builder/fieldRegistry.ts:54`（`REGISTRY`）、`:158-176`（`registerField`/`unregisterField`）
- **问题：** 模块加载时创建的全局可变对象，所有 FormBuilder/FormDesigner/FormCollect 实例共享。一处 `unregisterField` 影响所有页面所有实例。
- **建议：** 注册收敛为应用级显式 API，或删除 `unregisterField` 导出。

#### H7. FormRenderer 富文本用 `document.querySelector` 取编辑器 DOM，多实例/多字段串扰
- **文件：** `form-builder/FormRenderer.vue:222`（`document.querySelector('[data-richtext-editor]')`）
- **问题：** 一个表单含多个 richtext 字段（或多表单同页）时，永远取**第一个**匹配的编辑器写回当前字段——改字段 B 的工具栏，字段 A 的值被改动。
- **影响：** 所有含 ≥2 个 richtext 字段的表单。
- **建议：** 改用组件内 `ref`。

#### H8. 字段类型元数据存在 5 套并行枚举，无单一数据源
- **文件：** `form-builder/types.ts:27-59`（FieldType）、`designer/types.ts:32-54`（DesignerFieldType）、`designer/types.ts:360-424`（FIELD_TYPES）、`designer/types.ts:499-503`（FIELD_NODE_TYPES）、`fieldRegistry.ts:54-99`（REGISTRY）+ `:179-187`（BUILTIN_TYPES）、`OutlineTree.vue:119-152`、`PropsPanel.vue:260`
- **问题：** 新增一个字段类型要同步改 5-6 处；`FIELD_TYPES` 目前就缺 password/tel/email/url/search/combobox/tree-select/date-range/image-upload/camera 十个已注册类型，设计器左侧面板无法添加它们。fieldRegistry 声称"新增类型只需注册"是假的。
- **建议：** 以 fieldRegistry 为唯一事实源，其余全部派生。

#### H9. 存储 key 前缀与指纹算法在 store.ts 与 designer/types.ts 重复实现，且对 undefined key 处理不一致
- **文件：** `designer/types.ts:458-463`（`collectStorageKey` 用 `f.key ?? ''`）、`designer/store.ts:97-107`（saveForm 内联指纹用 `f.key`）
- **问题：** `fd_collect_` 前缀 + `f.key:f.type` 哈希在两处各写一遍。任何字段缺 key 时，types.ts 产出 `:type` 而 store.ts 产出 `undefined:type`——写进去的记录永远读不到。算法任一侧被改即破坏既有数据。
- **影响：** FormCollect（读）与 store.ts（写）的记录读写链路。
- **建议：** 收敛为单一导出函数，统一 undefined-key 处理。

#### H10. schema 版本号三处不一致
- **文件：** `useFormSchema.ts:25`（`SCHEMA_VERSION = 2`）、`designer/types.ts:952`（`toFormSchema` 硬编码 `schemaVersion: 3`）、`FormDesigner.vue:446/551`（导出 JSON 硬编码 3）
- **问题：** normalizeSchema 注入 2、toFormSchema 产 3、FormDesigner 导出 3，互相独立。
- **建议：** 版本号收敛到 useFormSchema 单一常量。

#### H11. DataTable 通过 useTableCore 中转导出 matchPinyin，依赖方向被扭曲
- **文件：** `data/composables/useTableCore.ts:8-9`、`data/composables/useTableFilter.ts:6`、`DataTable.vue:17`
- **问题：** useTableFilter 从 useTableCore 拿 matchPinyin，而 useTableCore 只是从 ./utils 中转。改 useTableCore 的导出即静默破坏 Filter 与 DataTable。
- **建议：** matchPinyin 归位 `./utils`，删除 useTableCore 中转导出。

#### H12. 主出口 index.ts 一锅端：单一 entry 构建一个 chunk，跨域互相拉入
- **文件：** `vite.config.ts`（`build.lib.entry = src/components/index.ts`）、`components/index.ts`（238 行混排 20+ 域）
- **问题：** 虽有 `sideEffects:false`，但 useVoice/useBeep 的模块顶层副作用无法被 tree-shake；chart、amap、form-builder、storage 重度域与 login、form 同 chunk。import 一个 Button 需解析全部依赖图。
- **建议：** 按域拆多 entry（preserveModules 类策略），index.ts 只保留跨域公共类型。

#### H13. useTableExtras 与 useTablePersistence 深度互绑（13 个具名 ref 的手写 options + 硬编码键名）
- **文件：** `data/composables/useTableExtras.ts:285-296`、`data/composables/useTablePersistence.ts`
- **问题：** 新增/删除持久化特性必须同时改两处 + options 类型 + DataTable 组装代码；键名 `dt${_ns}-${key}` 硬编码。
- **建议：** 重构为特性注册表，或合并回单文件。

## 四、最重要整改建议（按优先级）

1. **拆除共享可变单例（H1/H2/H6/H12）**：useModalManager、Toast 队列/`window.__toast`、fieldRegistry、z-top 全部改为"按实例/按作用域"隔离（Map keyed by scope 或 provide/inject）。这是"改一个组件影响全局"的根因。

2. **建立字段类型单一事实源（H8）**：类型枚举、中文名、图标、可编辑属性清单、渲染组件、布局标记全部收敛进 fieldRegistry，DesignerFieldType/FIELD_TYPES/BUILTIN_TYPES/PropsPanel/FormRenderer 全部由注册表驱动派生。当前改动成本最高、回报最大的耦合点。

3. **强制走公共出口（H4/H5 + M4）**：route-planner 全部深路径 import 改 `@/components/amap`，补齐 amap/index.ts 的 normalizeChinaLatLon；designer 子组件杜绝 `../FormRenderer.vue` 直连。

4. **收敛存储 key 算法（H9）**：collectKey 指纹只保留一处导出，统一 undefined-key 处理，store.ts 不再内联。

5. **按域拆构建入口（H12）**：vite lib 改多 entry（preserveModules），index.ts 不再单一 re-export；同时把 useVoice/useBeep 顶层副作用改为按需触发。
