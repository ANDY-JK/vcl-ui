# 06 · 测试审计

> 评分：**5 / 100**（测试系统名存实亡）

## 一、核心结论

**单元测试被全部删除，覆盖率 0%，CI 流水线与 git 提交钩子也被删除。测试是当前最严重的工程缺陷。**

## 二、证据

### 2.1 测试文件被删除

`git status --short tests/` 显示：

```
D tests/unit/Button.spec.ts
D tests/unit/Drawer.spec.ts
D tests/unit/Input.spec.ts
D tests/unit/Select.spec.ts
D tests/unit/Toast.spec.ts
```

这 5 个文件在 git 历史中是**被跟踪的**（`git ls-files tests/` 能列出），但工作区已删除。意味着：
- 曾经有 5 个核心组件的单元测试（Button/Drawer/Input/Select/Toast）；
- 现在物理文件已不存在，`vitest run` 报 `No test files found, exiting with code 1`。

### 2.2 覆盖率 0%

`npm run test:unit`（vitest --coverage）输出末尾：

```
ERROR: Coverage for lines (0%) does not meet global threshold (5%)
ERROR: Coverage for functions (0%) does not meet global threshold (5%)
ERROR: Coverage for statements (0%) does not meet global threshold (5%)
ERROR: Coverage for branches (0%) does not meet global threshold (4%)
```

vitest 配置里的阈值（statements 5 / branches 4 / functions 5 / lines 5）是「阶段性恢复目标」，但当前连 5% 都未达到——因为一个测试文件都没有。

### 2.3 CI 与钩子被删除

```
D .github/workflows/ci.yml
D .husky/pre-commit
```

CI 流水线（本应跑 typecheck+lint+test+build）与 husky pre-commit 钩子均被删除。这解释了为什么「测试被删 + 0 覆盖率」能进入主分支而无人拦截——质量门禁全部失效。

### 2.4 E2E 配置存在但无用例

- `playwright.config.ts` 配置完整（baseURL 3721、webServer 自动启动、chromium project）；
- 但 `tests/e2e/` 目录为空，无任何 Playwright 用例；
- `tests/fixtures/` 仅保留生成器（gen-fake-cam.mjs）在 git 中，产物 y4m 已 gitignore。

**结论**：测试工具链 100% 配齐，唯独「测试文件」被清空——这是典型的「配置在、用例亡」。

## 四、影响评估

| 风险 | 说明 |
|------|------|
| 无回归保护 | 任何改动（如正在进行的硬编码 px → CSS 变量重构、P1/P2 修复）都无法自动验证 |
| 安全漏洞无网兜底 | 富文本 XSS、eval 注入等修复后，无测试锁住行为 |
| 重构高风险 | git 显示 76 个文件处于 modified、13 个 deleted，在无测试下大量重构极易引入回归 |
| 发布无门禁 | 无 CI 意味着坏代码可直接合入主分支 |

## 五、恢复建议（优先级最高）

### 第 1 步：从 git 历史恢复被删测试

```bash
git checkout HEAD -- tests/unit/
```

这 5 个测试文件仍在 git 对象库中，可直接恢复。若历史版本已过时，再基于当前组件 API 重写。

### 第 2 步：恢复 CI

```bash
git checkout HEAD -- .github/workflows/ci.yml
git checkout HEAD -- .husky/pre-commit
```

### 第 3 步：重建测试覆盖（按组件重要性排序）

| 批次 | 组件 | 优先级理由 |
|------|------|-----------|
| 1 | Input / Select / Button / Group | 表单核心，安全相关（标签关联、伪控件） |
| 2 | DataTable / Tree / Pagination | 高频使用、逻辑复杂 |
| 3 | FormBuilder 系列 | 安全相关（富文本、联动 eval） |
| 4 | storage / indexedDB | 数据持久化正确性 |

### 第 4 步：补 E2E 冒烟

至少覆盖：登录页、DataTable 交互、FormBuilder 设计器保存/收集、Drawer/Modal 焦点管理。

## 六、目标

- 短期：恢复到「5 个核心组件 56 个测试」（vitest.config.ts 注释中提到的历史水平）；
- 中期：核心表单 + DataTable + storage 覆盖率 ≥ 30%；
- 长期：全库 statements ≥ 60%，并让 CI 覆盖率门槛真正生效。
