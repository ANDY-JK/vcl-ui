## 三、`any` 滥用（核心问题）

162 处 `any` 是最大技术债。典型分布集中在：

- `solar-icons-registry.ts`（图标注册表动态类型）
- DataTable / Select / Upload 等大组件的工具函数
- form-builder 的 schema 解析（动态 JSON schema 天然难类型化）

**影响**：`any` 会绕过类型检查，是运行时 bug 的温床。ESLint 目前配置为 `'warn'`（渐进式收紧），但未设置 `error` 门槛，导致其持续累积。

**建议**：
1. 将 `no-explicit-any` 提为 `error`，对存量用 `// eslint-disable-next-line` + 说明逐条豁免；
2. 优先修复 `_internal` 基建与公开 API 签名中的 `any`（下游影响面大）；
3. 对 JSON schema 解析用 `unknown` + 类型守卫替代 `any`。

## 四、其他质量问题

### 4.1 `vue/no-required-prop-with-default`（3 处）

`required: true` 与 `default` 同时存在是逻辑矛盾——required 的 prop 不会落到 default。需核对这 3 处是误设了 required 还是误设了 default。

### 4.2 无效 ruleId `null`（3 处）

eslint 报告中出现 `ruleId: null` 的消息（通常来自 parser 错误或 `/* eslint */` 注释异常）。建议定位这 3 处来源，确认是 parser 告警还是配置问题。

### 4.3 巨型函数与复杂模板

- DataTable 模板含 30+ 层嵌套条件渲染；
- `useFormLinkage.ts` 的表达式求值函数（60-115 行）逻辑分支多、可读性差，且用 `new Function`（见安全审计）。

### 4.4 注释与命名

- 组件头部注释普遍详实（如 `amap-key.ts`、`indexedDB.ts` 的定位说明），质量高；
- 但部分中文注释与代码混排，若未来做英文开源需统一。
