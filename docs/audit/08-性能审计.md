# 08 · 性能审计

> 评分：**70 / 100**

## 一、构建产物分析

`npm run build`（2026-08-23，6.81s，1136 模块）产物：

| chunk | 体积 | gzip | 说明 |
|-------|-----:|-----:|------|
| `vue-component-lib.js`（主包） | **1,162 kB** | 356 kB | 组件库主包，偏大 |
| `xlsx`（独立 chunk） | 758 kB | 193 kB | 已拆出，但体积巨大 |
| `login-chunk` | 285 kB | 67 kB | 登录域已懒加载 |
| `route-planner-chunk` | 73 kB | 23 kB | 路线规划已懒加载 |

## 二、主要问题

### 2.1 主包体积 1.16 MB（中高）

主包 gzip 后仍有 356 kB，超出「组件库主包应轻量」的预期。原因：
- `echarts`（即使 wordcloud 已动态 import，echarts 核心仍在主包或各图表 chunk）；
- `@iconify/vue` + `solar-icons`/`lucide-icons` 图标数据（`lucide-icons.json`、`solar-icons-data.json` 体积大）；
- `vue-i18n` + 120 条双语 locale。

**影响**：作为「通用组件库」，主包应尽量只含核心组件，重度依赖应全部按需。当前主包含大量图表/图标数据，对只想要 Button/Input 的消费者不友好。

### 2.2 xlsx 体积 758 kB（中）

- `xlsx` 已被 Vite 拆成独立 chunk（说明已做动态 import），这是进步；
- 但 758 kB 的单 chunk 仍会在「用到表格导入导出」时一次性加载，且 xlsx 是同步库、初始化开销大；
- 建议：仅在 `route-planner/utils/excel-import.ts` 真正 import xlsx 时按需加载，并考虑换用更轻的 `@e965/xlsx` 或后端导出。

### 2.3 图标全量打包风险（中）

`_internal/lucide-icons.json` 与 `solar-icons-data.json` 是**全量图标数据**（数千个图标）。若 IconSvg 组件 import 了整个 JSON，会导致所有图标进包。需确认 IconSvg 是否按需加载图标，还是全量引入。

## 三、做得好的地方

1. **按需 chunk 拆分**：login、route-planner、xlsx 均已拆成独立 chunk（login/route-planner 是懒加载路由，xlsx 是动态 import）。
2. **echarts-wordcloud 动态 import**：最近 commit（`9aa200c`）已把 echarts-wordcloud 改为动态 import，方向正确。
3. **构建速度快**：6.81s 完成 1136 模块，Vite 5 + esbuild 效率正常。
4. **CSS 独立产物**：234 kB CSS 单独输出，可被按需引用。

## 四、运行时性能观察（静态）

- **DataTable 虚拟滚动**：`useTableScrollProgress`、`useTableZoom`、`useTableFullscreen` 等 composables 表明表格有性能优化意识，但需确认大数据量下是否启用虚拟滚动（否则万行数据 DOM 会卡顿）。
- **Popover 竞态保护**：`Popover.vue` 用 RAF token 取消过期 show，避免了 hover 快速切换时的抖动，细节好。
- **防抖/节流**：`useDebounce`、`useFloating` 已具备，但需确认搜索/筛选输入是否都接了防抖。

## 五、改进建议

| 优先级 | 动作 | 预期收益 |
|--------|------|---------|
| P1 | 图标按需加载（tree-shaking 或动态 import 单个图标） | 主包可降 100–200 kB |
| P1 | 确认 echarts 是否按需引入（`echarts/core` + 按需 register） | 主包可降 200+ kB |
| P2 | xlsx 换轻量实现或彻底后置到服务端 | 消除 758 kB 峰值 |
| P2 | 为 DataTable 明确虚拟滚动策略 | 大数据量性能 |
| P2 | 全库输入类组件统一接防抖 | 交互流畅度 |

## 六、性能评分说明

70 分：按需拆分已开好头（login/route-planner/xlsx 已拆）、构建快、有性能优化意识（虚拟滚动 composables、竞态保护、防抖工具），扣分主因是**主包 1.16 MB 仍偏大**、图标/echarts 疑似未充分 tree-shaking、xlsx 单 chunk 过大。
