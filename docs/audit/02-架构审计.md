# 02 · 架构审计

> 评分：**72 / 100**

## 一、总体架构

组件库采用「**领域分层 + 内部基建隔离 + 统一出口**」架构：

```
src/
├── components/
│   ├── _internal/        # 内部基建：composables、i18n、icons、工具（不对外）
│   ├── basic/            # 基础：Button/IconSvg/Tag
│   ├── data/             # 数据展示：DataTable/Tree/Collapse/…(12)
│   ├── form/             # 表单：Input/Select/Group/Upload/…(6)
│   ├── feedback/         # 反馈：Toast/Drawer/Popover/…(10)
│   ├── nav/              # 导航：Tabs/Menu/Pagination/…(5)
│   ├── layout/           # 布局：AppLayout/ModalBox/Flex/…(7)
│   ├── chart/            # 图表：Chart/BaseChart/ChartTable/ChartLegend + options
│   ├── login/            # 登录：login/register/forgot/portal(4)
│   ├── storage/          # 存储：localStorage/IndexedDB/contract-storage
│   ├── amap/             # 高德地图封装
│   ├── route-planner/    # 路线规划（领域聚合）
│   ├── form-builder/     # 低代码表单平台（设计器+渲染+收集）
│   └── wc/               # Web Components 封装（未导出）
├── demos/                # 演示页（含 mini 小程序 demo）
└── index.ts              # 统一出口
```

## 二、优点

1. **职责清晰**：`_internal` 与公开组件分离，内部工具不污染公共 API；`options/`、`composables/`、`utils/` 子目录划分合理。
2. **基建复用度高**：`useFocusTrap`/`useClickOutside`/`useModalManager`/`useEscClose`/`useDebounce`/`useFloating`/`useScreenshot`/`useTheme`/`warnOnce`/`z-top` 等被多组件复用，说明设计者重视抽象。
3. **跨域一致**：i18n（`_internal/i18n.ts`）、图标（`solar-icons`/`lucide-icons`）、主题（`useTheme`）都是单点统一管理。
4. **领域聚合合理**：`route-planner` 与 `form-builder` 作为复杂业务域独立成目录，内部再分子模块（composables/utils/types/presets），组织清晰。
5. **模块化图表**：`chart/options/{core,advanced}` 将 20+ 种图表的 ECharts option 拆成独立文件，按需导入，方向正确。

## 三、问题

### 3.1 巨型单文件（高）

| 文件 | 行数 | 问题 |
|------|-----:|------|
| `data/DataTable.vue` | 3311 | 超大型"上帝组件"，模板+逻辑+样式混杂 |
| `data/ImagePreview.vue` | 1468 | 同上 |
| `form/Select.vue` | 1445 | 同上 |
| `form/Input.vue` | 923 | 边界 |
| `form-builder/FormRenderer.vue` | 915 | 边界 |

**影响**：可维护性差、变更风险高、单测难写、review 成本高。

**建议**：DataTable 已有 14 个 composables（`useTableCore`/`useTableFilter`/`useTableEdit` 等）已做了部分拆分，但模板仍集中在一个文件。应进一步把单元格渲染、表头、工具栏、分页拆成子组件。

### 3.2 领域耦合（中）

- `route-planner` 直接依赖 `amap`（`gaode-navigator.ts`、`coordinate-resolver.ts`），但 `amap` 又是独立公开域——依赖方向是 route-planner → amap，尚可，但缺少显式的内部依赖边界声明。
- `form-builder` 依赖 `form/Input`、`form/Select`（`fieldRegistry.ts` 中 `component: Input`），属合理的组件复用，但 form-builder 的字段渲染与 form 组件存在双向概念耦合（字段类型 ↔ 组件类型映射）。

### 3.3 未导出的 wc 域（低）

`src/components/wc/index.ts` 存在（导出 3 个），但 `src/components/index.ts` 主入口**未导出 wc 域**。Web Components 封装属"半成品"——要么补齐导出与文档，要么移除。

### 3.4 未导出的内部组件（低）

`layout/NavItem.vue` 是唯一未从主入口导出的 .vue 组件（被 `AccordionNav`/`MiniLayout` 内部使用）。这本身合理（内部组件），但缺 `_internal` 命名约定，建议加注释说明"内部组件，勿直接 import"。

### 3.5 图表 options 与组件分离但缺统一注册（低）

`chart/options/index.ts` 集中导出 20+ 图表 option 工厂，但 `Chart.vue`/`BaseChart.vue` 如何消费这些 option 需人工核对；缺少「图表类型 → option 工厂」的自动注册机制，新增图表需同时改多处。

## 四、依赖方向图（简化）

```
form-builder ──→ form (Input/Select/Group)
route-planner ──→ amap (key/service/navigator)
chart ──→ _internal (echarts-setup)
所有域 ──→ _internal (i18n/icons/composables)
index.ts ──→ 所有公开域
```

依赖方向总体向下（领域 → 基建），未发现循环依赖的明显证据（需 `madge` 进一步确认，本次未安装该工具以避免新增依赖）。

## 五、改进建议（按优先级）

1. **拆巨型组件**（DataTable/ImagePreview/Select 优先）。
2. **明确内部依赖边界**：route-planner 对 amap 的依赖应写成文档约定。
3. **决策 wc 域去留**：导出并补文档，或删除。
4. **图表类型注册表**：用映射替代散落的 switch/if。
5. **补 `madge` 循环依赖检查**到 CI（可选）。
