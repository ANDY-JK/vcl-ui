## 三、系统性全局问题

1. **无 skip link**（全库未实现「跳到主内容」）；
2. **应用级布局主体无 h1**（仅 login 域有）；
3. **手写浮层未复用焦点管理工具**（StorePanel 确认框、StoreFormModal、CameraCapture、Upload 底部菜单、MiniLayout 扫码层、ReadOnlyOverlay），导致焦点管理不一致。

## 四、修复优先级

| 级别 | 内容 |
|------|------|
| **P0（阻断）** | Input/Select 标签关联（`<label :for>` + input id）；Group radio/checkbox 改真实 input；ModalBox 关闭键加 aria-label；StoreFormModal/StorePanel 确认框接入 `useFocusTrap` |
| **P1（高影响）** | 统一 `div/span @click` → 语义按钮或补 role/tabindex/keyboard（TimeColumns、ToggleList、RouteResult 天头、Popover、login 社交按钮） |
| **P2（系统性）** | 图表/地图文本替代；手写弹层焦点管理；全局 skip link 与 h1 结构 |

## 五、无障碍成熟度评估

**51/100 的依据**：库内已有成熟实现（Drawer/ModalBox 的 useFocusTrap、Select combobox、Menu/Tabs/Steps/Pagination 的 ARIA 骨架、Upload 的 role=button），证明团队具备无障碍能力，基础分不低；但系统性缺陷（全库表单标签不关联、大量 div@click、自绘弹层焦点缺失、图表/地图无替代）拉低总分。修复是「把已有好实践推广到全库」，而非从零开始。
