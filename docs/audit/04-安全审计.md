# 04 · 安全审计

> 评分：**55 / 100**

## 一、高危发现

### 🔴 1. 富文本 `v-html` 未消毒（存储型 XSS）

**位置**：`form-builder/FormRenderer.vue:413`

```html
<div class="fb-richtext-body" contenteditable="true"
     v-html="richtextContent"
     @input="emit('update:modelValue', ($event.target as HTMLElement).innerHTML)" />
```

**问题**：富文本字段的内容**直接**通过 `v-html` 渲染，没有任何消毒步骤。用户可在 `contenteditable` 中粘贴 `<img onerror=...>`、`<script>`、`<a href="javascript:...">` 等恶意 HTML，保存后再次渲染即触发 XSS。

**对比（正例）**：`data/DataTable.vue` 的 `v-html` 都经过了 `sanitizeHTML()`（`data/composables/sanitize.ts`）白名单消毒，是正确做法。FormRenderer 却漏掉了这一步。

**建议**：
1. 立即对 `richtextContent` 做消毒（复用或抽离 `sanitizeHTML`，或引入 DOMPurify）；
2. 渲染时用 `sanitizeHTML(richtextContent)` 包裹；
3. `@input` 时也应对 innerHTML 做一次白名单过滤再 emit。

### 🔴 2. 联动表达式 `new Function` 动态求值（代码注入）

**位置**：`form-builder/useFormLinkage.ts:84,97,108`

```js
const result = new Function(`return (${expr})`)()
```

**问题**：`expr` 来自表单联动配置中的表达式（含 `{{fieldName}}` 占位符），经过字符串替换后直接 `new Function` 求值。若配置由不可信来源（如服务端下发的 schema、可被低权限用户编辑的表单设计）注入，攻击者可在表达式中嵌入任意 JS（如 `{{x}}; globalThis.alert(1)`）。

**缓解现状**：代码对字段值做了引号包裹转义（`val.replace(/"/g,'\\"')`），且表达式命中 `==/!=/>=` 或纯算术时才求值，降低了注入面，但**不足以构成安全边界**。

**建议**：
1. 用白名单表达式解析器（`jsep` 等）替代 `new Function`；
2. 或严格限制表达式为「字段引用 + 已知运算符」的语法树，禁止函数调用/属性访问/`globalThis`。

## 二、中危发现

### 3. 其余 `v-html`（DataTable 已消毒，需复核）

| 位置 | 是否消毒 |
|------|---------|
| `data/DataTable.vue:2547` | ✅ `sanitizeHTML(col.cell(...))` |
| `data/DataTable.vue:2762` | ✅ 同上 |
| `data/DataTable.vue:3135` | ✅ `sanitizeHTML(_tooltipText)` |

DataTable 三处均已消毒，`_tooltipText` 来自 `col.tooltip` 回调，仍建议在源头对用户可控的 `col.cell`/`col.tooltip` 返回值保持警惕。

### 4. `sanitizeHTML` 白名单的残余风险

`data/composables/sanitize.ts` 的白名单实现质量较高，但有以下注意点：
- 允许 `style` 属性且只过滤了 `expression/javascript:/url(javascript:)` 等模式，CSS 注入面较窄但仍存在（如 `background: url(data:text/html...)` 已覆盖，但 `-webkit` 前缀行为等边界需定期复核）；
- `href/src` 允许 `data:image/` 与 `#`，属合理范围。

### 5. 密钥管理（现状良好，但需注意）

- `amap-key.ts`：密钥统一走 `import.meta.env.VITE_AMAP_KEY`，未硬编码，✅ 良好。
- `.env.local` 含真实 Supabase anon key 与高德 key，已被 `.gitignore` 排除（`.env.local`、`.env.*.local`），✅ 未入库。
- **注意**：`.env.local` 中 Supabase **anon key** 是公开密钥（前端使用属正常），但注释中明确「数据库密码已移除，不要放前端」——需持续确保**服务端密钥（service_role key）绝不进入前端**。

### 6. 敏感数据存储

| 数据 | 存储位置 | 风险 |
|------|---------|------|
| 登录用户名/密码 | `login.vue` 用 `storageGet/Set`（走 localStorage） | 密码明文存 localStorage 属高风险，建议只存 token、不存密码 |
| 门店/路线数据 | `useStoreData.ts` localStorage | 业务数据，风险低 |
| 合同收集 | `contract-storage.ts` IndexedDB + Supabase | 见下方 |

`login.vue:150` 注释已说明「storageGet/Set 实际走 localStorage」。需确认「记住密码」功能是否真的把密码明文落地 localStorage——若存在，应改为「记住用户名」或仅存 token。

## 三、低危 / 观察项

- **无 `target="_blank"` 的 `rel="noopener"` 防护检查**：未系统扫描所有外链，建议加 ESLint 规则 `react/jsx-no-target-blank`（Vue 对应 `vue/no-target-blank`）到 CI。
- **无 CSP / SRI 配置**：作为组件库，运行时 CSP 由宿主应用负责，但应在文档中给出安全使用指引。
- **依赖漏洞**：详见 `05-依赖审计.md`（vue-i18n XSS、echarts XSS 属安全范畴，此处不重复）。

## 四、安全评分说明

扣分主因：**P0-4 富文本 XSS 与 P0-5 动态 eval** 是真实存在的、可被触发的漏洞，且测试清零导致「无回归网兜底」。加分项：密钥管理规范、DataTable 消毒实现、存储层 try-catch 防护。
