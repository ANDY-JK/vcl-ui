# 09 · 国际化审计（i18n）

> 评分：**38 / 100**

## 一、核心结论

**i18n 基建完整，但覆盖极低：61 个组件中仅 10 个接入 i18n（16%），全库 908 行硬编码中文。**

## 二、i18n 基建现状（良好）

- **机制**：`src/components/_internal/i18n.ts` 基于 vue-i18n 的 Composition API（`legacy: false`），默认 `zh-CN`，fallback 也是 `zh-CN`。
- **语言包**：`locales/zh-CN.ts` 与 `locales/en-US.ts` 各 **120 条**，数量对齐。
- **API**：`setLocale` / `getLocale` / `useT` / `useI18n` 导出齐全，且 `setLocale` 会同步更新 `<html lang>` 属性（正确做法）。
- **消费方友好**：组件内部用 `useT()` 无需 `app.use(i18n)`，测试环境也可用（注释已说明）。
- **主入口已导出**：`src/components/index.ts` 导出 `i18n / setLocale / getLocale / useT / useI18n` 与 `Locale` 类型。

## 四、问题分析

1. **「已接入但残留」现象**：DataTable（171 行中文但标记已用 i18n）说明接入不彻底——组件引入了 `useT` 但大部分文案仍硬编码，属于「接了但没接完」。
2. **优先级倒挂**：复杂的 form-builder 已接入 i18n，而基础的表单（Upload/CameraCapture）、登录、路线规划等用户直接面对的页面反而未接入。
3. **语言包只有 120 条**：相对 908 行硬编码中文（含大量文案），语言包容量明显不足，若要全量 i18n 化需把语言包扩充到数百条。

## 五、改进建议

| 优先级 | 动作 |
|--------|------|
| P1 | 先补「用户可见」域：login、route-planner、Upload、CameraCapture、ImagePreview |
| P1 | 清理 DataTable/FormDesigner 的「已接入但残留」的硬编码中文 |
| P2 | 扩充 locale 到全量文案，建立「新增文案必须走 locale」的编码约定 |
| P2 | 增加 ESLint 规则或 CI 检查：`.vue` 模板内出现中文字面量即告警（排除注释） |
| P2 | 补充英文 locale 的翻译质量审校（120 条需与中文逐一对齐语义） |

## 六、评分说明

38 分：基建（机制/API/双语包/导出）做得规范，加了不少分；但覆盖仅 16%、908 行硬编码、多个用户直面域未接入，把总分拉低。本质是「有 i18n 能力，但只用了十分之一」。
