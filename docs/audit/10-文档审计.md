## 二、主要问题

### 2.1 README 缺失（高）

- 根目录无 `README.md`，但 `package.json` 的 `files` 字段明确声明包含 `README.md`——打包时会缺失；
- 作为 npm 组件库，README 是消费者的第一入口（安装方式、快速上手、组件清单、License），缺失是重大文档缺口。

### 2.2 组件级示例不完整（中）

- `src/demos/` 有 40+ 个 demo 文件（含完整的 mini 小程序 demo），说明有演示素材；
- 但 `docs/` 下没有「每个组件的独立使用文档 + 代码示例 + API 表」的完整矩阵；
- `api-auto.md` 是自动生成的 API 文档，需确认其覆盖度（是否所有 props/emits/slots 都在）。

### 2.3 文档分散、无统一入口（中）

- 文档分布在 `docs/`（使用手册、api-auto、form-builder 审计）、根目录（eslint/vitest 报告）、`reports/`（空）多处；
- 缺一个「文档导航 README」串起所有文档。

### 2.4 文档时效性（低）

- `docs/form-builder-audit-report.md` 是单域审计（2026-08-22），本次全库审计（2026-08-23）应与之衔接，避免重复/冲突；
- 使用手册（2026-08-18）可能滞后于最近的组件变更（git 显示 76 文件 modified）。

## 三、做得好的地方

1. **使用手册**（51 KB）内容详实，说明团队有文档意识；
2. **API 自动文档**通过 `gen:docs` 脚本生成，可随代码更新（`npm run gen:docs`）；
3. **设计 mockup 齐全**，17 张设计稿/截图，说明设计与实现有对照；
4. **源码注释质量高**：组件头部注释（如 amap-key.ts、indexedDB.ts）详尽，可直接作为文档素材。

| 优先级 | 动作 |
