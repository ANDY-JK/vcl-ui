# 低代码表单设计器 — 功能差距盘点与完善路线（2026-08-30）

> 对应评审意见第 3 条「可用功能有点少，很多布局/功能还没完善」。基于代码审查 + 真实浏览器操作逐项核实。
> 结论先行：**核心链路（设计→预览→收集→保存→分享→存储切换）已全部可用**；「感觉少」主要是 4 个结构性缺口 + 若干体验级缺口，下面按影响排序，每项附现状/差距/建议。

## 已具备（实测可用，避免重复建设）

- **字段 37 种**：基础 23 + 高级 8（子表单/关联选择/富文本/签名/省市区/证件/评分矩阵/流水号）+ 布局 3（分割线/标题/说明文字）+ 容器 6（卡片/栅格/横排/标签页/折叠/步骤）
- **属性配置五页签**：基础/校验/样式/事件/数据，字段级几乎全覆盖
- **校验 14 种内置** + 自定义正则/条件；required/联动显隐/步骤间校验
- **布局运行时**：single/grid/flex/tabs/collapse/steps 六种容器完整渲染（本轮修复了 grid/flex 的 scoped 穿透与 span 语义）
- **数据收集**：记录列表/搜索分页/详情/Excel 导出/去重计数
- **表单管理**：保存/我的表单（打开/重命名/删除）/分享码（FD1. base64url 跨设备还原）/存储方式（本地/云端 Supabase 切换 + 连通测试）
- **设计器**：撤销/重做 50 步、多选批量删除、复制粘贴、导入导出 JSON（v1/v2/v3 兼容）、拖拽排序/跨容器、设备切换、大纲树/代码查看

## 完善路线建议

1. **先做 P0-1（发布/嵌入）**——这是「低代码」产品闭环的关键：设计器 → 发布 → 终端用户填写 → 数据回设计者。借助已有的分享码 + 存储层，增量最小（一个独立渲染页 + 路由）。
2. **再做 P0-4（拖拽插入）+ P1-6（远程数据源）**——设计期体验 + 表单能力两翼。
3. **P1-9（表单模板库）✅ 已闭环（2026-09-05，10 模板全量入选择器）**；P1 全清单收官。
4. **P2 全清单（10-13）✅ 已闭环（2026-09-05）**：快捷键面板/card 设计期视觉/设置五分组/设计器草稿自动保存，P0-P2 差距清单全部清零；验证脚本 `scripts/evidence-p2.cjs`（13/13 断言 + 4 截图）。
