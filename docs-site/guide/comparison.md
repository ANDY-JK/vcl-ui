# 与主流库对照

## 先说清这份对照的口径

**只写能核验的**。功能层面「谁有什么」需要逐版本文档核对，本库没有做这件事，所以
**不给功能矩阵**（那最容易变成过时或想当然的断言）。这里给出的是：

1. 来自 npm registry 的**客观包数据**（可复现，命令见文末）
2. 本库**自己的**能力与其**限制**（同硬度声明）
3. 差异点在哪 —— 这是选型真正需要的

::: warning 抓取时间
下表数据抓取于 **2026-10-21**，通过 `npm view <pkg> version license dist dependencies --json`
（registry.npmjs.org）。竞品会发版，**请以你自己查询时的结果为准**。
:::

## 本库的能力与限制（同硬度）

### 标配（主流 Vue 3 组件库普遍具备）

| 能力 | 本库状态 |
| --- | --- |
| TypeScript 优先 + `.d.ts` | ✅ 逐文件声明，`verify:pkg` 守可达性 |
| 设计令牌 / 主题 | ✅ 全量 `--vcl-*` 前缀，亮暗双主题 |
| 按需引入 | ✅ **按域多入口**（13 域独立产物） |
| i18n | ⚠️ 内置**只有 zh-CN / en-US** |
| 无障碍 | ⚠️ axe 扫描值守，但**无第三方审计**，24px 热区**有登记例外** |
| 暗色模式 | ✅ 属性驱动（非自动跟随系统偏好） |
| RTL | ❌ **未支持**（有立项清单，无实现） |

### 差异点（这几条不是标配）

**1. 按域多入口是「真隔离产物」，不是 tree-shaking 结果**

多数库的按需靠 unplugin 自动转换 + 打包器 tree-shaking；本库直接构建出
`vcl-ui/basic`、`vcl-ui/data`… 各自独立产物（**13 个域入口**）。引 basic 就**只加载** basic 与共享 core chunk。

**2. 低代码闭环（含数据接缝，不只是拖拽面板）**

设计器 → 表单落进宿主库 → 自动成为导航项 → 用户填写 → 记录落进宿主库，**全程不改代码、不重新构建**。
关键在**接缝声明得够硬**：`FormStore` 9 个方法 / REST 契约 4 组路由 / `useFormNav` 只产数据不渲染 UI /
权限过滤不在库内实现（库不知道谁该看哪个表单）。

**3. 跨框架出口（Web Components）与 Vue 版同源**

`vcl-*` 自定义元素可在 React / 原生页面直接用，与 Vue 版共用同一套令牌与行为基线。

**4. 闸口密度**

整链 **31 步**机械断言：按域覆盖地板、单文件行数止涨线、生成文档零漂移、
i18n 双侧对账、依赖树健康、版本三件套对齐、性能回归守护、console 噪音棘轮。
每道闸口都有**负向对照**（证明它真会红）。

> 这条是双刃剑：它让「不退化」可机械保证，也让**贡献门槛高**（提 PR 前要跑 10 分钟）。

**5. 可核验的留痕**

每次跑链落 `reports/quality-check-latest.json` + 每步独立日志，且**每次运行前清空**。
「上次真的跑过什么、哪步多久、失败在哪」都可查。

## 什么时候不该选它

诚实列出来：

- **你要成熟生态 / 大量第三方模板** —— 本库生态接近于零
- **你要 RTL / 多语言（超过两门）** —— 本库明确不支持/不内置
- **你要开箱即用的设计语言** —— 本库是令牌驱动的基础件，不做品牌视觉
- **你不能接受以「本地源码/link」方式接入** —— 它还没发 npm
- **你的团队不愿承担 10 分钟整链** —— 闸口密度是它的核心资产，绕过就失去大半价值

```bash
  npm view "$p" version license dist.unpackedSize dist.fileCount dependencies --json \
    | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const j=JSON.parse(s);console.log(j.version||'', j.license||'', j.dist?.unpackedSize||'', j.dist?.fileCount||'')})"
done
# 本库是否已发布：
npm view vcl-ui version   # 预期：失败（404 / E404）
```
