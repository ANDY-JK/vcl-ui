# RTL（从右到左）

::: warning 当前状态：**部分支持**
表单/导航/反馈/数据展示域的**水平间距与边框**已完成逻辑属性转换，
并用双向取证守卫住了；**定位类属性（`left`/`right`）与 `text-align` 尚未改造**。
完整状态见下方「支持矩阵」。
:::

## 契约（宿主需要知道的）

**库内组件不自行设置 `dir`，跟随文档流向。**

```html
<!-- 宿主在根元素设一次，全库跟随 -->
<html dir="rtl">
```

组件内部**不会**写 `dir="ltr"` 去"纠正"自己 —— 那会让 RTL 页面里出现方向错乱的小岛。
唯一的例外是代码/数字等**必须 LTR 的语义内容**（如金额、日期），它们用 `dir="ltr"` 局部声明。

## 已完成（有守卫）

### 1. 逻辑属性转换：77 处 / 32 文件

| 物理属性 | 转为 | 处数 |
| --- | --- | --- |
| `margin-left` / `margin-right` | `margin-inline-start` / `-end` | 46 |
| `padding-left` / `padding-right` | `padding-inline-start` / `-end` | 12 |
| `border-left` / `border-right`（含 `-color`/`-width`/`-style`） | `border-inline-start` / `-end` | 19 |

转换后 `src/components` 内这六类物理属性的命中数**全部为 0**。

### 2. 双向取证守卫 `check:rtl`

7 个代表路由 × `ltr`/`rtl` 各量一遍，断言三条：

1. **零横向溢出**（`scrollWidth <= clientWidth`）
2. **零元素越界**（可见元素 rect 不超出视口左右边界，**排除横向滚动容器内的内容**）
3. **方向确实生效**（`direction === 'rtl'`）—— 防止"测了但没切过去"导致假绿

```bash
npm run check:rtl          # 守卫模式
npm run check:rtl -- --report   # 施工看板（只报告不判失败）
```

已进整链（第 29 步），自起自停 dev server。

### 3. LTR 零回归验证

逻辑属性替换在 LTR 下**应该完全等价**（`start` = `left`），但"应该"不等于"确认"。
用 40 张截图（5 页 × 8 视口）做像素级对照：

- 改前 vs 改后：**40/40 像素完全相同**
- 对照：同代码连截两次也有 10 张不同（图表 canvas 抗锯齿），说明截图本身有噪声基线
- 中途曾出现 1 张 1.56% 差异（`w2560-data-table`），逐文件二分定位后确认是**一次性截图抖动**，
  重截后 0 像素差

## 未完成（明确列出）

| 项 | 处数 | 为什么没做 |
| --- | --- | --- |
| `left:` / `right:` 定位 | 166 / 80 | **需逐处裁决**：跟随文本起始侧的（关闭钮、浮层锚定）该转 `inset-inline-*`；固定物理角的（地图角标、全屏钮）必须保持物理值。盲改会把"LTR 碰巧正常"换成"双向都可能坏" |
| `text-align: left/right` | 10 / 8 | **不是机械替换**：表格数字列右对齐是**语义**（数字右对齐），转成 `start/end` 会让 RTL 下数字跑到左边，那是错的。只有"跟随文本流"的才该转 |
| `translateX(...)` | 16 | 物理量（轮播/画布拖拽）与方向量（菜单展开）混在一起，需逐处判断 |
| `border-radius` 四角 | 分散 | 跟随所在盒的流向，需逐处裁决 |
| JS 侧方向计算 | — | `useFloating` 的浮层定位、轮播偏移量都含方向量，要读 `getComputedStyle().direction` |

## 后续怎么继续

1. 先跑 `npm run check:rtl -- --report` 看当前基线（应为 0）
2. 按 `docs/rtl-立项清单-2026-09-30.md` §3 的分期推进 P2（数据展示域定位类）
3. 每改一批就重跑守卫 + 做一次 LTR 像素对照（**这是防"改坏了但测试全绿"的唯一手段**）
4. 全部完成后撤掉 README 的「RTL 硬边界」声明，并按组件更新上面的支持矩阵

::: tip 为什么先建守卫再改样式
立项清单原文：「逻辑属性替换若无 RTL 渲染取证兜底，等于把『LTR 下碰巧正常』换成『双向都可能坏』」。

RTL 改造最危险的形态是：把 `margin-left` 换成 `margin-inline-start`，LTR 下**看起来没变**
（因为 start = left），于是所有既有测试继续绿 —— 而 RTL 下可能整个错位。
**没有 RTL 断言，改动是无风险的假象。**
:::
