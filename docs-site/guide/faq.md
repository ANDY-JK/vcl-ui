# 常见问题（FAQ）

::: tip 一句话定位
这是一个**内部优先**的 Vue 3 组件库：**13 个域入口 / 66 组件**、按域多入口、设计令牌驱动、闸口密度高。
它不是「又一个 Element Plus」，差异点见 [特性对照](/guide/comparison)。
:::

::: info 口径（可自行核验）
域数取**构建入口**口径（`package.json` 的 `exports`）= **13**，与 `npm run gen:docs` 的「13 域 / 组件 66」一致。
`_internal` 与 `shared` 是内部支撑目录，**不出独立域入口**；覆盖地板管 14 项
（12 个域 + `_internal` + `shared`，`wc` 由 Web Components 专项覆盖）。
::: 

## 选型与定位

### 它发布到 npm 了吗？

**没有。** `package.json` 是 `2.0.0`，但 registry 上查不到 `vcl-ui`（`npm view vcl-ui version` 会失败）。
当前按本地 `link` 或直接引源码使用。这一点在 README 首段也已改为如实声明。

### 支持 Vue 2 吗？

不支持。Vue 3 优先（peer `vue ^3.5`），产物双格式 ESM + CJS，带逐文件 `.d.ts`。

### 必须用 TypeScript 吗？

不必，但**推荐**。宿主用 JS 也能跑，只是拿不到 props/事件/暴露方法的类型提示。
文档站的组件 API 表是**从源码 JSDoc 生成**的，注释缺失会让「说明」列变 `—`，有闸口拦这件事。

### 只有两种语言吗？

**是的，只有 `zh-CN` 与 `en-US`。** 内置语言包按域分块，支持宿主 i18n 共存与外部文案覆盖，
但**没有**第三门语言的官方包 —— 需要别的语言时请通过覆盖键值的方式补，而不是等库内置。

### 支持 RTL 吗？

**尚未支持。** 有一份立项清单（`docs/rtl-立项清单-2026-09-30.md`），但**没有可执行的 RTL 能力**。
如果你的产品要出海阿拉伯语/希伯来语，请先自行验证，别默认它能用。

### 无障碍到什么程度？

全站 `axe-core` 扫描值守（亮暗双主题），键盘导航/焦点陷阱/模态互斥/ESC 栈有专项回归。
但**没有第三方无障碍审计**，且 WCAG 2.2 的 24px 触控热区仍有**已登记例外**（见 `docs/` 内台账）。
「扫描 0 违规」不等于「合规认证通过」。

## 接入方式

### 三种引入方式怎么选？

| 方式 | 适用 | 代价 |
| --- | --- | --- |
| 主入口 `import { Button } from 'vcl-ui'` | 想省事、不在意体积 | 引哪个域都会带上主入口 chunk |
| 按域 `import { Button } from 'vcl-ui/basic'` | **推荐**。只加载该域 + 共享 core chunk | 需要各自引该域 CSS |
| Web Components `vcl-button` | React / 原生页面 | 体积更大，事件是 DOM 事件不是 Vue emit |

### 按域引入后样式不对？

按域产物**不会**自动带上全部样式。需要引该域的 CSS（构建产物里有域级 CSS 文件）。
`tokens.css` 是**必须**的，它定义所有 `--vcl-*` 设计令牌。

### 能只用设计令牌不用组件吗？

可以，`tokens.css` 可单独引入。断点令牌 `--vcl-bp-sm/md/lg` 与 JS 侧 `BP_SM/MD/LG` 同值，有闸口守。

## 行为与边界

### 事件名写 camelCase 还是 kebab？

**2.0 起统一 kebab-case**（`@row-click`）。模板里两种写法都能收到（Vue 编译器会归一），
但**测试断言**与文档口径以 kebab 为准。从 1.x 升级见 [迁移清单](/guide/migration-2.0)。

### 低代码能连我自己的数据库吗？

能，但**库不直连数据库**。走两条接缝：

- **表单存哪**：实现 `FormStore` 接口（或直接用 `createRestFormStore({ baseUrl })`，后端按约定实现 REST 路由）
- **表单提交到哪**：`submitConfig.saveUrl` 指向你的接收端点，地址由宿主在渲染时注入，**设计里不放死地址**

### 低代码的导航要自己写吗？

`useFormNav()` **只产出数据、不渲染导航 UI** —— 用什么导航组件是你的选择。
加载失败时 `error` 有值但 `items` 保留上一次结果（导航不该因一次网络抖动整条消失）。
权限过滤与分组**不在库内实现**，通过 `useFormNav({ filter })` 由宿主提供。

### 图表在测试/jsd 环境里不渲染？

`BaseChart` 在容器**任一维度为 0** 时**故意不初始化**（等 `ResizeObserver` 通知）。
jsdom 没有布局，所以测试里要么给元素打尺寸，要么断言「零尺寸不 init」这个行为本身。
这不是 bug，是避免 ECharts 在 0×0 上报警告并浪费一次 init。

### 数据源能接三种模式吗？

展示类元素（表格/图表/地图/结果态…）统一走 `displaySource`：

- `kind: 'static'` —— 面板里直接写数据
- `kind: 'field'` —— 绑定到表单字段
- `kind: 'api'` —— 远程拉取（受 `ApiUrlPolicy` 约束：默认同源，跨域需 `allowlist` + `allowCrossOrigin`）

::: warning 命名坑
展示数据源叫 `displaySource`；`dataSource` 是**下拉选项**的 `FieldDataSource`，两者不是一回事。
:::

## 工程与维护

### 为什么这么多闸口？

因为**靠人工守的纪律一定会回潮**。这个库单维护者 + AI，把「不许退化」变成机械断言是唯一可持续的路径。
当前整链 **40 步**，含覆盖地板、行数止涨线、文档漂移、i18n 双侧对账、依赖健康、性能回归、噪音棘轮等。

### 闸口会不会太严？

有意识地严。但每道闸口都配了**负向对照**（证明它真会红）和**噪声抑制**（比如性能闸口对
`< 2ms` 场景只报告不拦截、疑似回归自动重测一次）。见 [术语表](/guide/glossary) 里的「棘轮」。

### 发现文档和实现不一致怎么办？

以**源码与闸口**为准。文档站里组件 API 表是生成的（`npm run gen:docs`），
叙事页是手写的 —— 手写页过时会在 `check:docs` / `check:doc-completeness` 里露出，
但**没有闸口能保证叙事文案 100% 与实现同硬度**，发现即当 bug 提。
