# 国际化

## 内置语言包

库内置 `zh-CN` / `en-US` 两套语言包（按域分块，1429 键，`check:i18n` 闸口保证两侧同集）。默认中文，无需任何配置即可用。

## 三种接入方式

### 1. 使用库的 i18n 实例（最简单）

```ts
import { createApp } from 'vue'
import { i18n, setLocale } from 'vcl-ui/i18n'

const app = createApp(App)
app.use(i18n)

setLocale('en-US') // 随时切换
```

### 2. 与宿主应用自己的 i18n 共存

**没有 `vcl-ui/locales/*` 这类子路径**（`package.json` 的 `exports` 里只有 `./i18n`）。库自带一份 i18n 实例并以具名导出 `i18n` 暴露，组件内部走 `useT()`/`useTm()` 直连它的 `global.t`——因此**两个实例各管各的即可，不需要合并语言包**：

```ts
// 宿主自己的 i18n 照常创建，互不干扰
import { createI18n } from 'vue-i18n'
import { i18n as vclI18n, setLocale, registerMessages } from 'vcl-ui'

const hostI18n = createI18n({ legacy: false, locale: 'zh-CN', messages: { 'zh-CN': { myApp: {} } } })

// 若要给**库实例**补充宿主自己的文案，用 registerMessages 反向登记（不是把库的包导入宿主）：
registerMessages({ 'zh-CN': { myApp: { title: '我的应用' } } })
setLocale('zh-CN') // 库实例的当前语言
```

> 对照：`vclI18n` 就是库内那份实例；宿主不 `app.use(vclI18n)` 也能用（组件不依赖 inject 上下文）。

要点：

- 库内组件统一经 `useT()` / `useTm()` 取当前 i18n 实例的 `global.t`，**不需要** `useI18n()` 的 inject 上下文，因此不存在「组件在 provider 外渲染取不到翻译」的问题
- 键名是扁平点路径（`common.confirm`、`table.sheetData`），顶层键即命名空间
- 宿主语言优先：在宿主 messages 里覆盖同名键即可，不影响库源码

### 3. 运行时补充/覆盖文案

```ts
import { registerMessages } from 'vcl-ui/i18n'

registerMessages({
  'zh-CN': { common: { confirm: '项目自定义确认' } }, // 覆盖库同 key
  'fr-FR': { common: { confirm: 'Confirmer' } },      // 注册库没有的语言
})
```

需在 `app.use(i18n)` 之后、组件渲染前调用；未覆盖的键回退 `zh-CN`。

## 自定义组件复用库文案

```ts
import { useT, useTm } from 'vcl-ui'

const t = useT()
t('common.confirm') // → '确认'
```
